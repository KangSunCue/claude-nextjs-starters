# deploy-check

배포 전 사용자가 정의한 요구사항대로 모든 기능이 정상 작동하는지 단계별로 점검하고 테스트합니다.

## 실행 흐름

### 1단계 — 요구사항 파악
사용자에게 다음을 확인합니다:
- 이번 배포에서 검사할 핵심 요구사항 목록 (없으면 자동으로 프로젝트를 분석하여 추출)
- 테스트 환경 (로컬 / 스테이징 / CI)
- 중점 점검 영역 (기능 / 성능 / 보안 / UI)

### 2단계 — 프로젝트 자동 분석
프로젝트 구조를 파악하여 점검 항목을 자동 수집합니다:

```
- package.json / pyproject.toml 등에서 테스트 스크립트 탐지
- 환경변수 파일 (.env.example, .env.local) 누락 여부 확인
- 빌드 설정 파일 (next.config.js, vite.config.ts 등) 검토
- Git 상태 확인 (미커밋 변경사항, 브랜치 확인)
```

### 3단계 — 체크리스트 생성 및 순차 실행
아래 카테고리별로 항목을 점검하고 각 결과를 즉시 보고합니다.

#### ✅ 코드 품질
- [ ] Lint 오류 없음 (`eslint`, `pylint`, `ruff` 등)
- [ ] 타입 오류 없음 (`tsc --noEmit`, `mypy` 등)
- [ ] 포맷 통과 (`prettier`, `black` 등)

#### ✅ 테스트
- [ ] 단위 테스트 전체 통과
- [ ] 통합 테스트 통과 (있는 경우)
- [ ] 테스트 커버리지 기준 충족 (설정된 경우)

#### ✅ 빌드
- [ ] 프로덕션 빌드 성공 (`npm run build` 등)
- [ ] 빌드 산출물 크기 이상 없음
- [ ] 빌드 경고 검토

#### ✅ 환경 & 설정
- [ ] 필수 환경변수 모두 정의됨
- [ ] 프로덕션용 API endpoint 설정 확인
- [ ] 디버그 / 개발 전용 코드 미포함 확인

#### ✅ 보안 기초
- [ ] 의존성 취약점 없음 (`npm audit`, `pip-audit` 등)
- [ ] 시크릿 / API 키 코드에 하드코딩 없음
- [ ] CORS, 인증 설정 프로덕션 기준 적합

#### ✅ 사용자 정의 요구사항
사용자가 명시한 요구사항을 순서대로 하나씩 실제 동작을 확인하며 점검합니다.
각 항목마다:
1. 어떤 방식으로 검증할지 설명
2. 실제 명령어/코드 실행 또는 수동 확인 방법 안내
3. 통과 / 실패 / 경고 결과 즉시 출력

### 4단계 — 최종 보고서 출력

점검 완료 후 아래 형식으로 요약합니다:

```
=== 배포 전 점검 결과 ===

총 항목: N개
✅ 통과: N개
⚠️  경고: N개  
❌ 실패: N개

[실패 항목 상세]
- (항목명): (원인 및 해결 방법)

[경고 항목 상세]
- (항목명): (내용 및 권고 사항)

[배포 판정]
🟢 배포 가능  /  🔴 배포 보류 — 실패 항목 해결 필요
```

## 사용 예시

```
/deploy-check
```

```
/deploy-check 이번 배포에서 로그인 기능, 결제 플로우, 관리자 페이지 접근 제한을 중점적으로 확인해줘
```

```
/deploy-check 요구사항: 1) 회원가입 이메일 인증 작동 2) 상품 목록 필터 정상 동작 3) 모바일 반응형 레이아웃 깨짐 없음
```

## 주의 사항

- 실패 항목이 1개라도 있으면 배포 보류를 권고합니다.
- 경고 항목은 배포는 가능하나 반드시 다음 배포 전에 해결을 권장합니다.
- 사용자가 요구사항을 별도로 제공하지 않으면, 프로젝트의 README, 기존 테스트 파일, PR 설명에서 자동으로 추출합니다.
- 자동화로 검증하기 어려운 항목(UI 시각적 확인 등)은 수동 확인 가이드를 제시합니다.
